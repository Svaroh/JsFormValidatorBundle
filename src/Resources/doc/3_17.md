### 3.17 Comparing a field with another field

The Symfony comparison constraints accept a `propertyPath` option instead of a
`value`: the value to compare with is then read from another property of the
same object, not from a constant. `Range` has the same option twice, as
`minPropertyPath` and `maxPropertyPath`.

```php
class Booking
{
    public $startDate;

    #[Assert\GreaterThan(propertyPath: 'startDate', message: 'End smaller than start.')]
    public $endDate;
}
```

The bundle honours the option in the browser. When the field is validated, the
compared value is read from the form field the pointed property is bound to, at
that moment, so it always reflects what the user has typed there.

This works for `GreaterThan`, `GreaterThanOrEqual`, `LessThan`,
`LessThanOrEqual`, `EqualTo`, `NotEqualTo`, `IdenticalTo`, `NotIdenticalTo` and
`Range`.

A few details are worth knowing:

- The property path is resolved against the object the constraint belongs to,
  the same object Symfony resolves it against on the server. For a constraint
  declared on a property of a class, that object is the data of the parent form,
  so the path names a sibling field. For a constraint declared on the class
  itself, it is the data of the field carrying the constraint.
- Nested paths written with dots or brackets, `period.start` and `period[start]`,
  are followed through the embedded forms. Only paths made of property names are
  supported: the segments are looked up among the fields of the form, so a path
  reaching into an array key or a property with no field of its own is not
  resolved.
- A path that resolves to no field is not an error in the browser. The
  constraint stays silent and the server reports the mismatch after the form is
  submitted. That covers the properties a form does not expose, which the
  browser has no value for.
- The dependent field is validated when the form is validated, not when the
  referenced one changes. Editing `startDate` after `endDate` has been marked
  invalid does not clear the error by itself; the error is refreshed the next
  time `endDate` is validated. Wire a
  [custom event](3_12.md) on the referenced field if the errors have to follow
  every keystroke.
